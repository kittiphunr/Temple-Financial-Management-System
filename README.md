# ระบบบัญชีรายรับ-รายจ่ายวัด (จังหวัดแพร่)

[![Tests](https://github.com/kittiphunr/Temple-Financial-Management-System/actions/workflows/tests.yml/badge.svg)](https://github.com/kittiphunr/Temple-Financial-Management-System/actions/workflows/tests.yml)

ระบบ PHP + MySQL สำหรับบันทึกบัญชีรายรับ-รายจ่ายของวัด จัดกลุ่มวัดตามอำเภอทั้ง 8 อำเภอของจังหวัดแพร่
(เมืองแพร่, ร้องกวาง, ลอง, สูงเม่น, เด่นชัย, สอง, วังชิ้น, หนองม่วงไข่)

## ความสามารถ
- บันทึก/แก้ไข/ลบ (soft delete) รายรับและรายจ่าย แยกหมวด ผูกกับวัด
- **แดชบอร์ดรายอำเภอ** (`dashboard.php`): การ์ดสถิติ รายรับรวม/รายจ่ายรวม/ยอดคงเหลือ/จำนวนวัด, กราฟรายเดือน, หมวดสูงสุด, ตารางวัดในอำเภอ (บอกวัดที่ยังไม่บันทึกบัญชี)
  แอดมินหลักเลือกอำเภอหรือทั้งจังหวัดได้ เจ้าหน้าที่อำเภอเห็นเฉพาะอำเภอตน แอดมินวัดเห็นเฉพาะวัดตน
- สรุปภาพรวมรายปี (พ.ศ.) รายเดือน รายหมวด รายวัด จัดกลุ่มตามอำเภอ
- พิมพ์รายงาน / บันทึกเป็น PDF ผ่านเบราว์เซอร์ และส่งออก CSV (เปิดด้วย Excel ได้)
- บทบาทผู้ใช้: `admin` แอดมินหลัก (ทุกวัด), `province` เจ้าคณะจังหวัด (ดูได้ทั้งจังหวัด อ่านอย่างเดียว), `district` แอดมินอำเภอ (เฉพาะอำเภอ), `subdistrict` เจ้าคณะตำบล (เฉพาะตำบลที่ดูแล อ่านอย่างเดียว), `temple` แอดมินวัด (เฉพาะวัดตนเอง)
- **ติดตามการส่งรายงานประจำเดือน** (`report_status.php`, ต้องรัน migration ข้อ 10): วัดกด "ส่งรายงานประจำเดือน" ที่หน้ารายงานแบบที่ 1–3 (ระบบเก็บจำนวนรายการและยอดรวม ณ ตอนส่ง) — แอดมินหลัก/เจ้าคณะจังหวัด/แอดมินอำเภอ/เจ้าคณะตำบลดูได้ว่าวัดใด **ส่งแล้ว / ยังไม่ส่ง / เกินกำหนด / แก้ไขหลังส่ง** ตามขอบเขตของตน มีสรุปเปอร์เซ็นต์ กรองสถานะ ส่งออก CSV และแถบสรุปในแดชบอร์ด · กำหนดส่ง = วันที่ N ของเดือนถัดไป (แอดมินหลักตั้งได้ 1–28 ค่าเริ่มต้น 10) · แอดมินหลัก/แอดมินอำเภอส่งอีเมลเตือนวัดที่ค้างได้ (เฉพาะวัดที่มีอีเมล เดือนละครั้งต่อวัด) · แอดมินหลัก/แอดมินอำเภอส่งรายงานแทนวัดได้ เจ้าคณะจังหวัด/ตำบลดูอย่างเดียว
- **เมนูกระชับและไอคอน Feather**: แถบเมนูรวมเป็น 4 กลุ่ม dropdown (บันทึกบัญชี · การเงิน · รายงาน · ทะเบียน) + แดชบอร์ด/จัดการระบบ/บัญชีของฉัน แทนลิงก์ยาวแถวเดียว (จอแคบเป็นเมนู ☰ แยกหัวกลุ่ม) ปุ่มบัญชีของฉัน/ออกจากระบบแสดงเฉพาะไอคอนบนจอไม่กว้างมาก · ใช้ [Feather Icons](https://feathericons.com) (MIT) ผ่านฟังก์ชัน `icon('ชื่อ')` ทั่วระบบ: เมนู การ์ดแดชบอร์ด ปุ่ม แก้ไข/ลบ/พิมพ์/ส่งออก/กลับ การ์ดหน้าจัดการระบบ กล่องแจ้งเตือน และสถานะ (แทน emoji เดิม) · ไอคอนเป็นของประดับ (aria-hidden) มีข้อความกำกับเสมอ
- **การ์ดและช่องไฟมาตรฐาน**: กล่องเนื้อหาทั้งระบบใช้คลาสกลาง `.card` (ช่องว่างในการ์ด 1.25rem เท่ากันทุกด้าน ระยะห่างระหว่างการ์ด 1rem) · `.card-table` (การ์ดตาราง คอลัมน์แรก/สุดท้ายเว้นเท่ากับการ์ด) · `.card-bar` (แถบสั้น เช่น ตัวกรอง) · `.callout` (ข้อความแจ้ง/คำเตือน ใส่สีด้วยคลาสสี Tailwind) กำหนดใน `assets/css/input.css` — กริด/แถวที่ห่อการ์ดจัดช่องไฟให้เอง · ห้ามกำหนด padding/ขอบ/พื้นหลังของการ์ดเองในหน้าใหม่ (ชุดทดสอบ ui ตรวจให้) · ความสูงบรรทัดหัวข้อปรับให้ตัวอักษรไทยดูสมดุลบนล่าง
- **ลูกศร dropdown**: ช่องเลือก (select) วาดลูกศรเอง (Feather chevron-down) ชิดขวากึ่งกลางแนวตั้งเสมอ เว้นพื้นที่ด้านขวาไม่ให้ข้อความชนลูกศร เปลี่ยนสีเมื่อโฟกัส และช่องเลือกเดือนในช่องวันที่ใช้ชื่อย่อ (ม.ค. ก.พ. …) ให้พอดีกับช่องแคบ
- **ตัวควบคุมฟอร์มสมดุล**: ช่องกรอก ตัวเลือก (select) และปุ่มทุกแบบสูงเท่ากัน 2.75rem (44px) ขอบมนเท่ากัน (`rounded-xl` 12px) ปุ่มเล็ก (`.btn-sm`) สูง 2.25rem ขอบ 8px และฟอร์มขนาดใหญ่ (`.form-lg` ใช้ในหน้าบันทึกด่วน) สูง 3.5rem — ปุ่มขอบ (outline) กับปุ่มทึบสูงเท่ากัน จัดไอคอน+ข้อความกึ่งกลาง ช่องเลือกไฟล์มีปุ่มสไตล์เดียวกัน · กำหนดที่ `assets/css/input.css` ห้ามกำหนดความสูง/ขอบมนของตัวควบคุมเองในหน้าใหม่ (ชุดทดสอบ ui ตรวจโค้ดและวัดขนาดจริงในเบราว์เซอร์)
- **บันทึกด่วนบนมือถือ** (ไม่ต้องใช้ migration): เมนู "บันทึกด่วน" (`quick.php`) ฟอร์มสั้นปุ่มใหญ่สำหรับรับ/จ่ายเงินหน้างาน — เลือกรายรับ/รายจ่าย กรอกจำนวนเงิน (แป้นตัวเลข) เลือกหมวด (กรองตามประเภทให้) รายละเอียดไม่บังคับ เลือกบัญชีธนาคาร/กองทุนได้ บันทึกเป็นวันนี้ แล้วกลับหน้าเดิมพร้อมรายการล่าสุด 5 รายการ · บันทึกผ่านตัวเดียวกับหน้าบัญชี (ตรวจสิทธิ์ ปิดงวด เตือนงบ ครบเหมือนกัน) · แอดมินวัด/อำเภอ/หลักใช้ได้ (เจ้าคณะจังหวัด/ตำบลไม่มีเมนู)
- **สำรองข้อมูลและกู้คืน** (ไม่ต้องใช้ migration): เมนู จัดการระบบ → สำรองข้อมูล (`admin/backup.php`, แอดมินหลักเท่านั้น) สร้างไฟล์สำรอง `.sql.gz` ของฐานข้อมูลทั้งหมดด้วย PDO ล้วน (ไม่ต้องมี mysqldump) เก็บใน `storage/backups/` ที่เว็บเข้าไม่ถึง ดาวน์โหลด/ลบได้ · ตั้งสำรองอัตโนมัติทุก 1–30 วัน (เมื่อแอดมินหลักเปิดหน้าจัดการระบบ) หรือใช้ cron: `php backup.php --keep=14` · **กุญแจระบบ** (`storage/app.key` ที่เข้ารหัสเลขบัตร/ที่อยู่ผู้บริจาค) ไม่ถูกใส่ในไฟล์สำรอง ให้ดาวน์โหลดแยกแบบเข้ารหัสด้วยรหัสผ่านสำรอง (Argon2id) ต้องยืนยันรหัสผ่านปัจจุบันก่อน · กู้คืนด้วยบรรทัดคำสั่ง `php restore_backup.php ไฟล์.sql.gz --yes [--key=ไฟล์กุญแจ.json]` (ใช้ลงเซิร์ฟเวอร์ใหม่ได้ ไม่ต้องผ่านตัวช่วยติดตั้ง) · เวลา (TIMESTAMP) ล็อกเป็น UTC ตอนสำรอง/กู้คืน ข้อมูลจึงตรงกันแม้เขตเวลาต่างกัน · ชุดทดสอบกู้คืนแล้วเทียบ CHECKSUM ทุกตาราง
- **นำเข้ารายการจากไฟล์ธนาคาร** (ไม่ต้องใช้ migration): ที่หน้าบัญชีเงินสด/ธนาคาร กด "นำเข้ารายการจากไฟล์ธนาคาร (CSV/Excel)" อัปโหลด statement เป็น .csv (UTF-8 หรือ Windows-874/TIS-620 ตัวคั่น , ; หรือแท็บ) หรือ .xlsx ระบบเดาแถวหัวตารางและคอลัมน์ วันที่/รายการ/ถอน/ฝาก (หรือจำนวนเงินช่องเดียวติดลบ) ให้เอง แก้เองได้ถ้าเดาไม่ถูก · รองรับวันที่ ค.ศ./พ.ศ. หลายรูปแบบ เลขวันที่ของ Excel และเดือนภาษาไทย · หน้าตัวอย่างให้เลือกหมวดของแต่ละรายการ (จำหมวดที่เคยใช้กับรายการชื่อเดียวกัน) แก้รายละเอียด และข้ามรายการที่มีอยู่แล้วให้ (ไม่ติ๊กไว้) · แถวสรุปยอด/วันที่อ่านไม่ได้/เดือนที่ปิดงวดแล้วนำเข้าไม่ได้ · ไม่เก็บไฟล์ต้นฉบับ · แอดมินวัด/อำเภอ/หลักเท่านั้น (ไฟล์ไม่เกิน 5 MB, 3,000 แถว)
- **ทะเบียนผู้บริจาค (PDPA)** (ต้องรัน migration ข้อ 17): เมนู "ผู้บริจาค" เก็บเฉพาะผู้ที่ให้ความยินยอม — ต้องติ๊กยืนยันความยินยอมและเลือกช่องทางที่ได้รับ ระบบบันทึกวันเวลาและผู้บันทึก · ที่อยู่และเบอร์โทรเก็บแบบเข้ารหัสด้วยกุญแจระบบ · หน้าออกอนุโมทนาบัตรเลือกผู้บริจาคจากทะเบียนแล้วเติมชื่อ-ที่อยู่ให้อัตโนมัติ หรือบันทึกผู้บริจาคใหม่ตอนออกใบ (ต้องยืนยันความยินยอม) · ดูประวัติและยอดบริจาคตามใบที่ออก · **ถอนความยินยอม** ได้ทุกเมื่อ ระบบลบชื่อ/ที่อยู่/เบอร์/หมายเหตุในทะเบียนทันที (ใบที่ออกไปแล้วยังเก็บสำเนาชื่อ-ที่อยู่ตามหลักฐานทางบัญชี) · การเปิดดูรายละเอียดบันทึกใน audit log · เฉพาะแอดมินวัด/อำเภอ/หลัก (เจ้าคณะจังหวัด/ตำบลไม่เห็นข้อมูลส่วนบุคคลของผู้บริจาค)
- **รูปภาพเก็บเป็น WebP**: รูปที่อัปโหลดทุกชนิด (ตราวัด 512 px, รูปบุคลากร/ทรัพย์สิน 600×800 px, หลักฐานแนบด้านยาว 2000 px) ถูกย่อตามโปรไฟล์และแปลงใหม่เป็น WebP ด้วย GD ไฟล์เล็กลงมาก คงความโปร่งใสของตราวัด (ถ้า GD ไม่รองรับ WebP จะใช้ PNG/JPEG แทนอัตโนมัติ) · รูปเดิมที่เก็บไว้ก่อนหน้าแปลงได้ด้วย `php convert_images.php` (ทดลองรัน) แล้ว `php convert_images.php --apply` — สำรองฐานข้อมูลก่อนรันจริง
- **ทะเบียนทรัพย์สิน** (ต้องรัน migration ข้อ 16): เมนู "ทรัพย์สิน" บันทึกที่ดิน อาคาร/สิ่งปลูกสร้าง ครุภัณฑ์ ยานพาหนะ ฯลฯ — เลขทะเบียน (ไม่ซ้ำในวัด) วันที่และวิธีได้มา มูลค่า สภาพ สถานที่ ผู้รับผิดชอบ รายละเอียด (เช่น เลขโฉนด ทะเบียนรถ) และรูป (แปลงใหม่ด้วย GD เปิดผ่าน `media.php` ที่ตรวจสิทธิ์) · ที่ฟอร์มบันทึกรายจ่ายเลือก "ทรัพย์สินที่ซื้อ/ซ่อม" ได้ ระบบรวมต้นทุนซื้อและค่าซ่อมสะสมที่หน้ารายละเอียดทรัพย์สิน · จำหน่ายทรัพย์สินต้องระบุวันที่และเหตุผล (ข้อมูลยังเก็บไว้ ยกเลิกการจำหน่ายได้) · กรองตามประเภท/สภาพ ค้นหา พิมพ์ทะเบียนพร้อมช่องลงนาม และส่งออก CSV · แอดมินวัด/อำเภอ/หลักจัดการได้ เจ้าคณะจังหวัด/ตำบลดูได้ตามขอบเขต
- **กองทุน/โครงการ** (ต้องรัน migration ข้อ 15): เมนู "กองทุน/โครงการ" สร้างกองทุนของวัด (เช่น กฐิน ผ้าป่า สร้างอาคาร กองทุนการศึกษา) พร้อมเป้ายอดได้ แล้วเลือกที่ช่อง "กองทุน/โครงการ" ตอนบันทึกรายรับ-รายจ่าย ระบบสรุปรับ/ใช้/คงเหลือสะสมและร้อยละของเป้า มีหน้ารายงานรายกองทุนพร้อมยอดคงเหลือต่อรายการและพิมพ์ได้ · ชื่อกองทุนเป็นวัตถุประสงค์เริ่มต้นบนอนุโมทนาบัตร · กองทุนที่ปิดแล้วเลือกกับรายการใหม่ไม่ได้ แต่รายการเดิมยังอยู่ · แอดมินวัด/อำเภอ/หลักจัดการได้ เจ้าคณะจังหวัด/ตำบลดูได้ตามขอบเขต
- **งบแสดงรายรับ-รายจ่ายประจำปี** (ไม่ต้องใช้ migration): ที่หน้ารายงานกด "งบแสดงรายรับ-รายจ่ายประจำปี" เลือกวัดและปี พ.ศ. ได้งบรายวัดเทียบปีก่อน (ร้อยละการเปลี่ยนแปลง) เทียบงบประมาณ (ถ้าตั้งไว้) เงินคงเหลือยกมาต้นปี–ปลายปีแยกตามบัญชี และสรุปกองทุน/โครงการ พร้อมช่องลงนาม พิมพ์/บันทึก PDF ได้
- **งบประมาณประจำปี** (ต้องรัน migration ข้อ 14): เมนู "งบประมาณ" ตั้งงบรายหมวด (รายรับ/รายจ่าย) ของแต่ละวันต่อปี พ.ศ. เทียบกับผลจริงที่บันทึก (ไม่นับรายการที่ลบและรายการโอน/ฝาก-ถอน) แสดงคงเหลือ ร้อยละที่ใช้ และสรุปแผนรายรับ−รายจ่าย · หมวดรายจ่ายที่ใช้ถึง 80% เตือนสีเหลือง เกินงบเป็นสีแดง และเตือนทันทีตอนบันทึกรายจ่าย · คัดลอกงบจากปีก่อนได้ (เติมเฉพาะหมวดที่ยังไม่ได้ตั้ง) · แอดมินวัด/อำเภอ/หลักตั้งงบได้ เจ้าคณะจังหวัด/ตำบลดูได้ตามขอบเขต · เป็นเครื่องมือเตือน ไม่ห้ามบันทึกรายการที่เกินงบ
- **กระทบยอดบัญชีธนาคาร** (ต้องรัน migration ข้อ 13): ที่หน้าบัญชีเงินสด/ธนาคาร กด "กระทบยอดกับ statement" เลือกเดือนที่สิ้นสุดแล้ว ติ๊กรายการที่ขึ้นใน statement แล้ว กรอกยอดคงเหลือสิ้นเดือนตาม statement — ระบบคำนวณ ยอดสมุด − เงินฝากระหว่างทาง + รายจ่ายที่ธนาคารยังไม่หัก เทียบกับ statement แสดง ✅ ตรงกัน หรือส่วนต่าง · รายการที่ไม่ติ๊กยกไปเดือนถัดไป · มีประวัติ 12 เดือน และเตือนเมื่อมีการแก้รายการหลังกระทบยอด · แอดมินวัด/อำเภอ/หลักบันทึกได้ เจ้าคณะจังหวัด/ตำบลดูได้ตามขอบเขต · ไม่ล็อกรายการและไม่แก้ยอดบัญชี (เป็นเครื่องมือตรวจสอบ)
- **แนบหลักฐานใบเสร็จ/สลิป** (ต้องรัน migration ข้อ 12): กดปุ่ม 📎 ที่รายการในบัญชีรายรับ/รายจ่าย แนบภาพ JPEG/PNG/WebP หรือ PDF ได้สูงสุด 5 ไฟล์ต่อรายการ ไฟล์ละไม่เกิน 4 MB — ภาพถูกแปลงใหม่ด้วย GD (ลบข้อมูลแฝง EXIF/GPS, ย่อด้านยาวไม่เกิน 2000 px) เก็บในฐานข้อมูล เปิดผ่าน `attachment.php` ที่ตรวจสิทธิ์ทุกครั้ง (ไม่แคช) · แอดมินวัด/อำเภอ/หลักแนบและลบได้ เจ้าคณะจังหวัด/ตำบลดูได้ตามขอบเขตแต่แนบไม่ได้ · เดือนที่ปิดงวดแล้วแนบ/ลบไม่ได้ · สลิปมีข้อมูลส่วนบุคคล ควรตั้ง `upload_max_filesize` ≥ 4M (ดู `deploy/php.ini.recommended`)
- **ปิดงวดรายเดือน** (ต้องรัน migration ข้อ 11): หลังสิ้นเดือนและส่งรายงานแล้ว (ยอดตรงกับปัจจุบัน) แอดมินวัด/แอดมินหลัก/แอดมินอำเภอกด "ปิดงวดเดือนนี้" ที่หน้ารายงานประจำเดือน — เดือนที่ปิดแล้ว **เพิ่ม/แก้ไข/ลบรายการ รายการโอน/ฝาก-ถอน ไม่ได้ทุกบทบาท** (รวมแอดมินหลัก) ส่งรายงานใหม่และแก้ยอดยกมา/เพิ่มบัญชีธนาคารใหม่ไม่ได้ · **เปิดงวด** ทำได้เฉพาะแอดมินหลัก/แอดมินอำเภอ ต้องระบุเหตุผล (เก็บประวัติปิด/เปิดงวดและ audit) · เมื่อเปิดงวดแล้วแก้ไข ต้องส่งรายงานใหม่ก่อนปิดซ้ำ · รายการที่ล็อกแสดง 🔒 ในบัญชีรายรับ-รายจ่าย และกรองสถานะ "ปิดงวดแล้ว" ได้ที่หน้าติดตามรายงาน · อนุโมทนาบัตรยังออก/ยกเลิกได้ (ไม่กระทบยอดบัญชี)
- **เจ้าคณะตำบล** (`admin/subdistricts.php`, แอดมินหลักสร้าง): บทบาท `subdistrict` ดูข้อมูลได้อย่างเดียว เฉพาะวัดใน **ตำบลที่ได้รับมอบหมาย** (1 บัญชีดูได้หลายตำบล ตำบลอ้างอิงจากอำเภอ+ชื่อตำบลของวัด) — ดูแดชบอร์ด รายงานสรุป/CSV รายงานประจำเดือนแบบที่ 1–3 และรายชื่อบุคลากร (เลขบัตรและที่อยู่ปิดบัง) บันทึกบัญชี ออกอนุโมทนาบัตร และแก้ไขข้อมูลวัดไม่ได้ ต้องมีอีเมลรับรหัส 2FA เหมือนผู้ใช้ระดับจังหวัด/อำเภอ **ไม่นับในโควตา**
- **โควตาผู้ใช้ระดับจังหวัด**: แอดมินอำเภอ (1 คน/อำเภอ) + แอดมินหลัก + เจ้าคณะจังหวัด = จำนวนอำเภอ + 2 (แพร่ 8 อำเภอ = **10 คน**) คำนวณจากตาราง `districts` จึงใช้กับจังหวัดอื่นได้เมื่อเปลี่ยนรายการอำเภอ — จัดการที่ จัดการระบบ → ผู้ใช้
- **โลโก้**: แอดมินวัดอัปโหลดโลโก้วัดที่ "ข้อมูลวัดของฉัน" (ระบบเตือนด้วยแบนเนอร์จนกว่าจะใส่); โลโก้อำเภอเป็นหน้าที่ของแอดมินหลักที่ จัดการระบบ → โลโก้อำเภอ ใช้เป็นหัวกระดาษและช่องลงนามในรายงาน/เอกสารพิมพ์
- **อนุโมทนาบัตร** (`receipt.php`, `receipts.php`): รายรับในหมวดรับบริจาคมีปุ่ม "อนุโมทนาบัตร" — กรอกชื่อ/ที่อยู่ผู้บริจาค ระบบออกเลขที่ต่อเนื่องรายวัดรายปี พ.ศ. (เล่มที่ X เลขที่ N/ปี) แปลงจำนวนเงินเป็นตัวอักษร ใส่หัวกระดาษ/โลโก้วัด เลขผู้เสียภาษีของวัด ช่องลงนามผู้รับเงินและเจ้าอาวาส และตราประทับ พิมพ์เป็น A4 ได้
  ออกได้เฉพาะแอดมินวัดนั้นและแอดมินหลัก (แอดมินอำเภอดูได้) ยกเลิกต้องระบุเหตุผลและเลขที่จะไม่ถูกนำกลับมาใช้ รายการที่ออกใบแล้วแก้/ลบไม่ได้จนกว่าจะยกเลิกใบ แอดมินหลักกำหนดหมวดรับบริจาคที่ จัดการระบบ → หมวดบัญชี
- **เอกสารที่พิมพ์ได้**: อนุโมทนาบัตร, รายงานสรุปรายปี/รายเดือน/รายหมวด/รายวัด, บัญชีรายรับ/รายจ่าย (หัวกระดาษ + ช่องลงนาม), แดชบอร์ด, ส่งออก CSV
- โลโก้ระบบและไอคอนเว็บ = ตราคณะสงฆ์จังหวัดแพร่ (`assets/img/logo.svg`)
- **บุคลากรวัด** (`people.php`): เจ้าอาวาส พระลูกวัด ไวยาวัจกร เพิ่มได้ไม่จำกัด พร้อมเลขบัตรประชาชน ที่อยู่ตามภูมิลำเนาเดิม รูปถ่าย เบอร์โทร
  - เลขบัตรประชาชนเข้ารหัส (libsodium) ตรวจหลักตรวจสอบ แสดงแบบปิดบัง ดูเลขเต็มได้เฉพาะแอดมินหลักและแอดมินวัดนั้น (บันทึก audit); แอดมินอำเภอ/เจ้าคณะจังหวัดเห็นเฉพาะข้อมูลที่ปิดบัง ไม่เห็นที่อยู่
  - รูปเก็บในฐานข้อมูล แปลงใหม่ด้วย GD (ตัด EXIF) และเสิร์ฟผ่าน `media.php` ที่ตรวจสิทธิ์เท่านั้น
  - ต้องติ๊กยืนยันว่าได้รับความยินยอมจากเจ้าของข้อมูล (PDPA) ก่อนเพิ่มบุคคล
- **ต้องสำรอง `storage/app.key`** (กุญแจเข้ารหัสเลขบัตร) ไว้ที่ปลอดภัย — ถ้าหาย เลขบัตรที่บันทึกไว้จะถอดรหัสไม่ได้ (หรือกำหนดเองผ่าน config `app_key` / env `TFMS_APP_KEY`) ต้องเปิดส่วนขยาย PHP `sodium`, `gd`, `fileinfo`
- ระบบจัดการ (`admin/`): วัด, นำเข้ารายชื่อวัด (Excel/CSV), ผู้ใช้, หมวดบัญชี, ประวัติการใช้งาน (audit log)
- **นำเข้าทะเบียนวัดจากไฟล์ Excel ใช้กับจังหวัดอื่นได้** (`admin/import.php`, แอดมินหลักเท่านั้น): อัปโหลดไฟล์ .xlsx รายงานทะเบียนวัดจาก [binfo.onab.go.th](https://binfo.onab.go.th/Temple/Temple-List-view.aspx) ได้ตรง ๆ ไม่ต้องแก้ไฟล์ — ระบบอ่านคอลัมน์จากหัวตาราง (รหัสวัด ชื่อวัด ประเภท นิกาย วันที่ตั้ง ตำบล อำเภอ จังหวัด รหัสไปรษณีย์ โทรศัพท์ อีเมล์ หมู่บ้าน เลขที่ หมู่ ซอย ถนน) มีหน้าตรวจสรุปก่อนบันทึก (วัดใหม่/อัปเดต/ข้าม/อำเภอ) แล้วจึงยืนยัน
  - ใช้เริ่มระบบในจังหวัดอื่น: ติดตั้งโดยติ๊กออก "นำเข้าทะเบียนวัดจังหวัดแพร่" → นำเข้า Excel ของจังหวัดนั้น → ระบบ **สร้างอำเภอ** (รหัสจากรหัสวัด) **ตั้งชื่อจังหวัดของระบบ** (หัวเอกสาร/รายงาน/ข้อความใต้ชื่อระบบ) และ **ลบอำเภอตัวอย่างของแพร่ที่ว่าง**; สร้างบัญชีแอดมินวัด 1 วัด 1 บัญชี; โควตาผู้ใช้ระดับจังหวัดปรับตามจำนวนอำเภอ (+2) เอง
  - ไม่ลบข้อมูลเดิม (วัดที่มีอยู่แล้วอัปเดตเฉพาะช่องที่ไฟล์มีค่า), อีเมลวัดนำเข้าเฉพาะเมื่อติ๊กและวัดนั้นยังไม่มีอีเมล, ปีที่ตั้งวัดเก็บตามไฟล์ (พ.ศ.), ต้องเปิดส่วนขยาย PHP `zip` (ไม่มีก็ใช้ CSV ได้); ตรา/โลโก้ระบบ (`assets/img/logo.svg`) เปลี่ยนเป็นของจังหวัดนั้นเอง
  - ยังต้องทำเองต่อ: ใส่โลโก้อำเภอ, สร้างแอดมินอำเภอ/เจ้าคณะจังหวัด, ลงอีเมลวัด, เปลี่ยน `assets/img/logo.svg` และข้อความในไฟล์ตั้งค่า (ถ้าต้องการ)
- **รายงานประจำเดือนตามแบบฟอร์มของวัด** (`statements.php`, ตามโฟลเดอร์ `ตัวอย่างเอกสาร/`): **แบบที่ 1** บัญชีรายรับ-รายจ่าย (เงินสด), **แบบที่ 2** บัญชีรายรับ-รายจ่าย (เงินฝากธนาคาร — 1 ตาราง = 1 บัญชี), **แบบที่ 3** รายงานเงินคงเหลือ ณ สิ้นเดือน (ตัวอักษรไทย) — เลือกวัด/เดือน/ปี พ.ศ. พิมพ์เป็น A4 (แบบ 1-2 แนวนอน, แบบ 3 แนวตั้ง) หรือบันทึกเป็น PDF มีช่องลงนามผู้จัดทำบัญชี (ไวยาวัจกร) และเจ้าอาวาสตามแบบ
  - ใช้ได้โดยกรอก **ยอดยกมา** ของเงินสดและบัญชีธนาคารแต่ละบัญชีที่หน้า **"ข้อมูลวัด"** (`profile.php` ส่วน "บัญชีของวัด" — แอดมินวัดกรอกเอง มีแบนเนอร์เตือนจนกว่าจะตั้งยอดยกมาเงินสด) หรือที่ `accounts.php` (ซึ่งมีส่วนโอน/ฝาก-ถอนระหว่างบัญชีด้วย) ระบบคำนวณยอดคงเหลือต่อให้ทุกเดือน
  - เลือก "บัญชี" (เงินสด หรือธนาคารใด) ทุกครั้งที่บันทึกรายรับ-รายจ่าย; การนำเงินสดฝากธนาคาร/ถอนเงิน บันทึกเป็น "โอน/ฝาก-ถอน" ซึ่งไปปรากฏเป็นรายจ่ายของบัญชีต้นทางและรายรับของบัญชีปลายทางในแบบที่ 1-2 แต่ **ไม่นับ** เป็นรายรับ-รายจ่ายของวัดในแดชบอร์ดและรายงานสรุป
  - ชุดทดสอบ `statements` ใช้ "โจทย์ตัวอย่าง" วัดสยามเทวา ม.ค.-ก.พ. 2568 แล้วตรวจว่าตัวเลขทุกช่องตรงกับเฉลยในแบบตัวอย่าง

- **วันที่ทุกจุดเป็น พ.ศ.**: ฟอร์มกรอกวันที่เป็นช่องเลือก วัน/เดือน/ปี พ.ศ. (ไม่ใช้ `<input type="date">` ที่แสดงปีตามเบราว์เซอร์) ตรวจว่ามีวันนั้นจริง; หน้าจอ รายงาน ประวัติการใช้งาน และไฟล์ CSV ที่ส่งออกแสดงเป็น พ.ศ. ฐานข้อมูลเก็บเป็น ค.ศ. ภายใน (ฟังก์ชัน `date_be_field`, `date_be_parse`, `th_date` ใน `includes/bootstrap.php`)
- **การแจ้งเตือนด้วย SweetAlert2**: ข้อความสำเร็จเป็นป้ายมุมจอ ข้อผิดพลาดเป็นกล่องแจ้ง และกล่องยืนยันก่อนลบ/ดำเนินการ (`data-confirm` บนฟอร์มหรือปุ่ม) ไฟล์ไลบรารีอยู่ในเครื่อง (`assets/vendor/`, ไม่พึ่ง CDN) ไม่มี JavaScript ก็ยังเห็นข้อความเป็นแถบและฟอร์มส่งได้
- **หน้าต่าง "เกี่ยวกับระบบ · ผู้พัฒนา"** (ปุ่มท้ายทุกหน้า): หน่วยงาน ผู้พัฒนา ช่องทางติดต่อ และคำอธิบายระบบ แก้ข้อมูลที่ `includes/about.php`
- ความปลอดภัย: PDO prepared statements, CSRF token, `password_hash`, จำกัดสิทธิ์ตามขอบเขต, กัน CSV formula injection

## ติดตั้ง
ต้องการ PHP 8.1+ (ส่วนขยาย pdo_mysql, mbstring; แนะนำ openssl) และ MySQL 5.7+ / MariaDB 10.3+ (ชุดทดสอบผ่านบน MariaDB 10.11 และ MySQL 8.0 ทั้งการติดตั้งและโหมด strict — รันอัตโนมัติใน GitHub Actions ทุก PR)

### วิธีที่ 1: ตัวช่วยติดตั้งบนเว็บ (เหมือน WordPress)
วางโค้ดบนเว็บเซิร์ฟเวอร์ (Apache/Nginx + PHP-FPM, ใช้ HTTPS) ให้ผู้ใช้เว็บเซิร์ฟเวอร์เขียนโฟลเดอร์โปรเจกต์และ `storage/` ได้ชั่วคราว
แล้วเปิดเว็บไซต์ — ถ้ายังไม่ได้ติดตั้ง ระบบจะพาไปที่ `install.php` อัตโนมัติ ตัวช่วยพาทำทีละขั้น:

1. **ตรวจความพร้อม** — เวอร์ชัน PHP ส่วนขยาย สิทธิ์เขียนไฟล์ HTTPS
2. **ฐานข้อมูล** — โฮสต์/พอร์ต/ชื่อฐานข้อมูล/ผู้ใช้/รหัสผ่าน ทดสอบการเชื่อมต่อ สร้างฐานข้อมูลให้ถ้ายังไม่มี (ไม่เขียนทับฐานข้อมูลที่มีข้อมูลระบบอยู่แล้ว)
3. **จังหวัดที่ดูแลและข้อมูลเบื้องต้น** — (ก) เลือก **จังหวัด** จากรายการ 77 จังหวัด (ใช้ในหัวเอกสาร รายงาน อนุโมทนาบัตร) พร้อมชื่อระบบและคำอธิบายใต้ชื่อ (ข) **ทะเบียนวัด**: ใช้ชุดจังหวัดแพร่ 381 วัดที่มากับระบบ (เฉพาะแพร่) / **อัปโหลดไฟล์ Excel (.xlsx จาก binfo.onab.go.th) หรือ CSV ของจังหวัดนั้น** — ระบบสร้างอำเภอ วัด และตัดอำเภอตัวอย่างของแพร่ออกให้ (ตรวจว่าไฟล์เป็นของจังหวัดที่เลือก) / ยังไม่นำเข้า (ไปนำเข้าภายหลัง) พร้อมเลือกสร้างบัญชีวัดอัตโนมัติ และ **สร้างอำเภอและผู้ใช้ระดับจังหวัด/อำเภอ/ตำบลให้ครบจากฐานข้อมูลจังหวัด** (ค) ชื่อผู้ใช้/รหัสผ่านแอดมินหลัก (อย่างน้อย 10 ตัว มีตัวอักษรและตัวเลข)
4. **อีเมล** — ตั้งค่า SMTP พร้อมปุ่มส่งอีเมลทดสอบ (ใช้ส่งรหัสยืนยัน 2 ชั้นของวัด)
5. **ติดตั้ง** — สร้างตาราง นำเข้าข้อมูล สร้างบัญชี เขียน `config.local.php` (สิทธิ์ 0640) แล้วดาวน์โหลดรหัสผ่านเริ่มต้นของแต่ละวัดเป็น CSV **ได้ครั้งเดียว**

ติดตั้งเสร็จจะสร้าง `storage/installed.lock` ตัวช่วยจะใช้งานไม่ได้อีก (403) — แนะนำให้ลบ `install.php` ออกจากเซิร์ฟเวอร์ด้วย
ติดตั้งใหม่ได้โดยลบ `storage/installed.lock` และ `config.local.php` ด้วยตนเองเท่านั้น
ป้องกันคนอื่นเปิดตัวช่วยก่อนคุณ: ตั้งตัวแปรสภาพแวดล้อม `TFMS_INSTALL_KEY=รหัสลับ` ตัวช่วยจะถามรหัสนี้ก่อนเริ่ม
ระบบที่ติดตั้งไว้แล้วด้วยวิธีอื่น (มีผู้ใช้ในฐานข้อมูล) จะถูกตรวจพบว่าติดตั้งแล้วและไม่ถูกเปิดตัวช่วยซ้ำ

**กรุงเทพมหานคร:** เมื่อเลือกกรุงเทพมหานคร ทั้งระบบเรียก **เขต/แขวง** แทน อำเภอ/ตำบล (หน้าจอ รายงาน หัวเอกสาร ที่อยู่ ชื่อบัญชีที่สร้างอัตโนมัติ เช่น แอดมินประจำเขต/เจ้าคณะแขวง) และไม่ใส่คำว่า "จังหวัด" หน้าชื่อ — ฟังก์ชันอยู่ใน `includes/thai_geo.php` (`unit_district()`, `unit_subdistrict()`, `province_phrase()`, `address_tail()`) ข้อความใหม่ที่เรียกอำเภอ/ตำบลต้องใช้ฟังก์ชันเหล่านี้ ห้ามพิมพ์คำตรง ๆ

### ผู้ใช้ระดับจังหวัด/อำเภอ/ตำบล (สร้างอัตโนมัติ)
ตัวช่วยติดตั้ง (ติ๊ก "สร้างบัญชีผู้ใช้ระดับจังหวัด/อำเภอ/ตำบล"), `php setup.php` (ค่าเริ่มต้น; ข้ามด้วย `--no-staff`) หรือปุ่ม **สร้างบัญชีที่ยังว่างทั้งหมด** ที่ จัดการระบบ → ผู้ใช้ระดับจังหวัด/อำเภอ สร้างบัญชีให้ทุกตำแหน่งที่ยังว่าง (ทำซ้ำได้ ไม่แตะบัญชีเดิม) โดยอิง **ฐานข้อมูลจังหวัด/อำเภอ/ตำบลของประเทศไทย** (`data/thai_geo.json` 77 จังหวัด 930 อำเภอ/เขต 7,436 ตำบล/แขวง จาก [kongvut/thai-province-data](https://github.com/kongvut/thai-province-data) MIT — สร้างใหม่ด้วย `python3 tools/build_thai_geo.py <โฟลเดอร์โปรเจกต์นั้น>`): ผู้ติดตั้งเลือกจังหวัดของตน ระบบสร้างอำเภอครบทุกอำเภอ และผู้ใช้ทุกระดับ **แม้ยังไม่มีไฟล์ทะเบียนวัด** (นำเข้าทะเบียนวัดภายหลัง วัดจะเข้ากับอำเภอ/ตำบลที่สร้างไว้ตามชื่อ — ชื่อที่สะกดต่างกันและรหัสตำบลในรหัสวัดตรงกันจะให้เจ้าคณะตำบลคนเดิมดูแลทั้งสองชื่อ):

| ตำแหน่ง | ชื่อผู้ใช้ | จำนวน |
|---|---|---|
| แอดมินหลัก | ตามที่ตั้งตอนติดตั้ง (`admin` ถ้าใช้ `setup.php`) | 1 |
| เจ้าคณะจังหวัด (ดูอย่างเดียว) | `province` | 1 |
| แอดมินประจำอำเภอ | `amphoe<รหัสอำเภอ>` เช่น `amphoe5401` | อำเภอละ 1 |
| เจ้าคณะตำบล (ดูอย่างเดียว) | `tambon<รหัสตำบล 6 หลัก>` เช่น `tambon540207` (รหัสท้องถิ่นของกรมการปกครองจากฐานข้อมูลจังหวัด) ตำบลที่ไม่พบในฐานข้อมูล ใช้ `tambon<รหัสอำเภอ>x01` | ตำบลละ 1 |

รหัสผ่านเริ่มต้นเป็นค่าสุ่ม 12 ตัว ดูได้ครั้งเดียวจากไฟล์ CSV (`storage/staff_accounts_*.csv` หรือปุ่มดาวน์โหลด) ในฐานข้อมูลเก็บเฉพาะแฮช · ผู้ใช้ต้องตั้งรหัสผ่านใหม่เองตอนเข้าสู่ระบบครั้งแรก · **แอดมินหลักต้องลงอีเมลของแต่ละบัญชีก่อน** (จัดการระบบ → ผู้ใช้ระดับจังหวัด/อำเภอ และ เจ้าคณะตำบล) จึงจะเข้าสู่ระบบได้ เพราะทุกบัญชีต้องยืนยันรหัส 6 หลักทางอีเมล

## บัญชีวัดและการยืนยันตัวตนสองชั้น (2FA)
- **1 วัด = 1 บัญชี** สร้างอัตโนมัติตอนติดตั้ง (`php setup.php`), ตอนนำเข้ารายชื่อวัด และตอนเพิ่มวัดใหม่ — ฐานข้อมูลกันบัญชีที่ 2 ของวัดเดียวกันด้วย unique key
- **ชื่อผู้ใช้ถูกล็อก** ตั้งอัตโนมัติเป็น `wat` + รหัสวัด 11 หลัก (เช่น `wat03540118002`) ไม่มีหน้าจอใดแก้ชื่อผู้ใช้ได้ แม้แก้ชื่อวัดภายหลังก็ไม่เปลี่ยน
- **รหัสผ่านเริ่มต้นสุ่ม** ให้แอดมินหลักดาวน์โหลดเป็น CSV **ได้ครั้งเดียว** หลังสร้างบัญชี (ในฐานข้อมูลเก็บเฉพาะแฮช) —
  ตอนติดตั้งด้วย CLI จะเขียนไฟล์ `storage/temple_accounts_*.csv` (สิทธิ์ 0600) ให้นำไปแจกวัดแล้วลบทิ้ง
- **บังคับเปลี่ยนรหัสผ่านครั้งแรก:** แอดมินวัดที่เข้าสู่ระบบด้วยรหัสผ่านเริ่มต้นที่แอดมินหลักเตรียมไว้ให้ เมื่อผ่านรหัสยืนยันทางอีเมลแล้ว
  จะถูกพาไปหน้า "ตั้งรหัสผ่านใหม่" ทันที และใช้หน้าอื่นไม่ได้จนกว่าจะเปลี่ยน (ต้องไม่ซ้ำกับรหัสเริ่มต้นหรือชื่อผู้ใช้)
  การที่แอดมินหลักรีเซ็ตรหัสผ่านให้วัดก็บังคับเปลี่ยนอีกครั้งเช่นกัน
- **แอดมินวัดเปลี่ยนรหัสผ่านตัวเองได้** ที่เมนู "บัญชีของฉัน" (ต้องกรอกรหัสเดิม) แต่เปลี่ยนชื่อผู้ใช้และอีเมลไม่ได้
- **อีเมลวัด** แอดมินหลักเป็นคนสืบเสาะแล้วกรอกที่ จัดการระบบ → บัญชีวัด (กรอกทีละวัด หรือนำเข้า CSV `รหัสวัด,อีเมล`
  โดยดาวน์โหลดแม่แบบจากหน้าเดียวกัน) แก้ไขได้เฉพาะแอดมินหลัก
- **วัดที่ยังไม่มีอีเมลเข้าสู่ระบบไม่ได้** แม้รหัสผ่านถูก จนกว่าแอดมินหลักจะลงอีเมล
- **ล็อกอินสองชั้น (เฉพาะบัญชีวัด):** หลังรหัสผ่านถูก ระบบส่งรหัส 6 หลักไปอีเมลวัด ต้องกรอกก่อนเข้าระบบ
  รหัสใช้ได้ครั้งเดียว หมดอายุ 10 นาที กรอกผิดได้ 5 ครั้ง ขอรหัสใหม่ได้ทุก 60 วินาที (สูงสุด 5 ครั้ง/30 นาที) เก็บเฉพาะค่าแฮช
  การเปลี่ยนหรือลบอีเมลทำให้รหัสที่ค้างอยู่ใช้ไม่ได้ทันที
- รหัสผ่านผิดครบ 5 ครั้ง บัญชีถูกล็อก 15 นาที (แอดมินหลักรีเซ็ตรหัสผ่านเพื่อปลดล็อกได้)
- **แอดมินหลัก แอดมินอำเภอ และเจ้าคณะจังหวัด ก็ต้องยืนยันรหัส 6 หลักทางอีเมลเช่นกัน** (ค่าเริ่มต้นเปิด):
  - แอดมินหลัก: ครั้งแรกหลังติดตั้ง/อัปเกรด ระบบให้ลงทะเบียนอีเมลและยืนยันด้วยรหัสก่อนเข้าระบบ เปลี่ยนอีเมลภายหลังที่ "บัญชีของฉัน" (ต้องใส่รหัสผ่านและยืนยันรหัสที่อีเมลใหม่)
  - แอดมินอำเภอ/เจ้าคณะจังหวัด: แอดมินหลักลงอีเมลให้ที่ จัดการระบบ → ผู้ใช้ (ไม่มีอีเมล = เข้าระบบไม่ได้)
  - ปิดได้เฉพาะกรณีฉุกเฉิน (เช่น ตั้ง SMTP ไม่ได้ ทำให้แอดมินเข้าระบบไม่ได้): `'staff_2fa' => false` ใน `config.local.php` หรือ `TFMS_STAFF_2FA=0` — แล้วรีบแก้ SMTP และเปิดกลับ
  - แอดมินหลักเสียอีเมล (เข้าอีเมลเดิมไม่ได้): ให้ผู้ดูแลเซิร์ฟเวอร์รัน `UPDATE users SET email = NULL, email_verified_at = NULL WHERE username = 'admin';` แล้วเข้าสู่ระบบเพื่อลงทะเบียนอีเมลใหม่
- **ลืมรหัสผ่าน** (`forgot.php` → `reset.php`): กรอกชื่อผู้ใช้ ระบบส่งรหัส 8 หลักไปที่อีเมลที่ลงทะเบียนไว้ (บัญชีวัด = อีเมลวัด) ใช้ได้ครั้งเดียว หมดอายุ 15 นาที ผิดได้ 5 ครั้ง ตอบเหมือนกันไม่ว่ามีชื่อผู้ใช้นี้หรือไม่ และกู้รหัสสำเร็จจะปลดล็อกบัญชีที่ถูกล็อกด้วย บัญชีที่ไม่มีอีเมลให้ติดต่อแอดมินหลักรีเซ็ตให้

### ตั้งค่าการส่งอีเมล
ตั้งตัวแปรสภาพแวดล้อม (หรือแก้ `config.php`) — ถ้าไม่ตั้ง SMTP วัดจะขอรหัสไม่ได้และเข้าสู่ระบบไม่ได้

```bash
TFMS_MAIL_DRIVER=smtp          # smtp | mail (PHP mail()) | log (ทดสอบเท่านั้น เขียน storage/mail.log)
TFMS_SMTP_HOST=smtp.example.org
TFMS_SMTP_PORT=587
TFMS_SMTP_SECURE=tls           # tls (STARTTLS) | ssl | none
TFMS_SMTP_USER=...  TFMS_SMTP_PASS=...
TFMS_MAIL_FROM=no-reply@your-domain.org
```
อย่าใช้ driver `log` บนเซิร์ฟเวอร์จริง (รหัส 2FA จะถูกเขียนลงไฟล์) และบนเว็บเซิร์ฟเวอร์ต้องห้ามเข้าถึง `storage/`
(มี `.htaccess` สำหรับ Apache แล้ว; Nginx ให้ `deny all` เอง)

### ฐานข้อมูลที่ติดตั้งไว้ก่อนมีฟีเจอร์นี้
ต้องรัน `sql/migrations/*.sql` ตามลำดับ (ครั้งเดียวต่อไฟล์) หลังสำรองฐานข้อมูล — ขั้นตอนเต็ม การตรวจว่าอยู่รุ่นไหน ข้อควรตรวจก่อนรัน และสิ่งที่ต้องทำหลังอัปเกรด ดู **[UPGRADE.md](UPGRADE.md)**

## การจัดหน้า (Tailwind CSS)
ทุกหน้าใช้ Tailwind CSS 3 จัดหน้า รองรับมือถือ/แท็บเล็ต/เดสก์ท็อป และพิมพ์รายงานได้ (`print:` variants)
ไฟล์ `assets/css/tailwind.css` ที่ build แล้วถูก commit ไว้ ใช้งานบนเซิร์ฟเวอร์ PHP ได้เลยโดยไม่ต้องมี Node
ถ้าแก้ class ใน `*.php` หรือ `assets/css/input.css` / `tailwind.config.js` ให้ build ใหม่:

```bash
npm install
npm run build:css      # หรือ npm run watch:css ระหว่างพัฒนา
```

ธีมสี `brand` (แดง) และ `gold` (ทอง) กำหนดใน `tailwind.config.js` ฟอนต์ Sarabun โหลดจาก Google Fonts

## ข้อมูลวัดจังหวัดแพร่
`setup.php` โหลดทะเบียนวัดจริง 381 วัด จาก `data/temples_phrae.csv` (แปลงจาก `Report_Temple.xlsx`
ทะเบียนวัดของสำนักงานพระพุทธศาสนา) พร้อมตำบล หมู่ที่ รหัสวัด 11 หลัก ประเภทวัด และนิกาย ทุกวัดมีสถานะ "ตรวจสอบแล้ว"

| อำเภอ | วัด | อำเภอ | วัด |
|---|---|---|---|
| เมืองแพร่ | 95 | สอง | 40 |
| ลอง | 60 | เด่นชัย | 31 |
| วังชิ้น | 52 | หนองม่วงไข่ | 9 |
| สูงเม่น | 48 | ร้องกวาง | 46 |

- ชื่อวัดในไฟล์ต้นฉบับไม่มีคำว่า "วัด" นำหน้า สคริปต์แปลงจึงเติมให้
- วัดที่ชื่อซ้ำกันแยกด้วยรหัสวัด/ตำบล (เช่น "วัดน้ำชำ" มี 2 แห่งในอำเภอเมืองแพร่)
- ไฟล์ต้นฉบับมีรายการที่ถูกแก้ไขชื่อ/ที่ตั้งในคอลัมน์หมายเหตุ (เช่น โปร่งศรี → โป่งศรี) ซึ่งช่องชื่อวัดเป็นชื่อล่าสุดแล้ว
- อัปเดตทะเบียนภายหลังได้ที่ จัดการระบบ → นำเข้ารายชื่อวัด หรือสร้าง CSV ใหม่ด้วย
  `python3 tools/build_temples_csv.py Report_Temple.xlsx data/temples_phrae.csv`
- ข้อมูลเจ้าอาวาสและโทรศัพท์ไม่มีในทะเบียน แก้ไขได้ที่ จัดการระบบ → จัดการวัด

## เลขเวอร์ชันและหมายเลขบิวล์

เลขเวอร์ชันอยู่ในไฟล์ `VERSION` รูปแบบ `MAJOR.MINOR.PATCH` และขึ้นทีละระดับ: แก้ไขเล็กน้อยเพิ่มหลักที่ 3 (1.9.0 → 1.9.1) ส่วนอัปเดตใหญ่เพิ่มหลักที่ 2 แล้วหลักที่ 3 กลับเป็น 0 (1.9.x → 1.10.0) · **หมายเลขบิวล์**สร้างอัตโนมัติตอน `bash deploy/build.sh` (จำนวนคอมมิตสะสม เก็บใน `version.json` ของชุดติดตั้ง และตั้งชื่อไฟล์ `tfms-<เวอร์ชัน>-b<บิวล์>.zip`) แสดงในหน้าต่าง "เกี่ยวกับ" ของระบบ — ระบบที่รันจากซอร์สโดยตรงแสดง "(dev)" · ถ้า build ใน CI ที่ clone แบบตื้น ให้ตั้ง `BUILD_NUMBER` เอง
