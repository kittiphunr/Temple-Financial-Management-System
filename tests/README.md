# ชุดทดสอบ

ทดสอบระบบแบบ end-to-end ผ่าน HTTP จริง (`php -S`) กับฐานข้อมูลจริง และเซิร์ฟเวอร์ SMTP ปลอมที่อยู่ในตัวชุดทดสอบเอง
ใช้เฉพาะไลบรารีมาตรฐานของ Python ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

## วิธีรัน
```bash
# ต้องมี: python3, PHP 8.1+ (CLI + pdo_mysql) และ MySQL/MariaDB ที่เชื่อมต่อได้ด้วยบัญชีที่สร้าง/ลบฐานข้อมูลได้
export TFMS_TEST_DB_HOST=127.0.0.1 TFMS_TEST_DB_PORT=3306   # ค่าเริ่มต้น
export TFMS_TEST_DB_USER=root      TFMS_TEST_DB_PASS=...    # บัญชีที่มีสิทธิ์ CREATE/DROP DATABASE

python3 tests/run_all.py              # ทุกชุด (ใช้เวลาราว 1 นาที)
python3 tests/run_all.py features     # เฉพาะชุดฟีเจอร์หลัก
python3 tests/run_all.py install      # เฉพาะตัวช่วยติดตั้ง + บังคับเปลี่ยนรหัสผ่าน
python3 tests/run_all.py people       # เฉพาะโลโก้ / บุคลากร / โควตาผู้ใช้
python3 tests/run_all.py receipts     # เฉพาะอนุโมทนาบัตร
python3 tests/run_all.py auth         # เฉพาะ 2FA ของแอดมิน + ลืมรหัสผ่าน
python3 tests/run_all.py ui           # เฉพาะ SweetAlert2 + หน้าต่างเกี่ยวกับ + เมนู/ไอคอน + เลขเวอร์ชัน
python3 tests/run_all.py statements   # เฉพาะรายงานแบบที่ 1-3 + บัญชีเงินสด/ธนาคาร
python3 tests/run_all.py import       # เฉพาะนำเข้าทะเบียนวัดจาก Excel (ไฟล์จริงแพร่ + ไฟล์สังเคราะห์จังหวัดน่าน)
python3 tests/run_all.py quick        # เฉพาะหน้าบันทึกด่วนบนมือถือ
python3 tests/run_all.py backup       # เฉพาะสำรอง/กู้คืนข้อมูล (กู้แล้วเทียบ CHECKSUM ทุกตาราง กุญแจระบบ สำรองอัตโนมัติ สิทธิ์)
python3 tests/run_all.py bankimport  # เฉพาะนำเข้ารายการจากไฟล์ธนาคาร (CSV/Excel วันที่ พ.ศ. ตัดซ้ำ ปิดงวด สิทธิ์)
python3 tests/run_all.py donors       # เฉพาะทะเบียนผู้บริจาค (ความยินยอม PDPA การเข้ารหัส เชื่อมอนุโมทนาบัตร ถอนความยินยอม)
python3 tests/run_all.py bankbook      # เฉพาะบัญชีเงินฝากหลายบัญชี ตัวเลือกธนาคารพร้อมโลโก้ และภาพหน้าบุ๊คแบงก์
python3 tests/run_all.py images       # เฉพาะขนาดรูป/แปลง WebP และเครื่องมือ convert_images.php
python3 tests/run_all.py assets       # เฉพาะทะเบียนทรัพย์สิน (รูป ผูกรายจ่าย จำหน่าย สิทธิ์ CSV)
python3 tests/run_all.py funds        # เฉพาะกองทุน/โครงการ และงบแสดงรายรับ-รายจ่ายประจำปี
python3 tests/run_all.py budget       # เฉพาะงบประมาณประจำปี (ตั้งงบ เทียบผลจริง เตือนเมื่อใกล้/เกินงบ สิทธิ์)
python3 tests/run_all.py reconcile    # เฉพาะกระทบยอดบัญชีธนาคาร (ติ๊กรายการ ส่วนต่าง รายการค้างยกไป สิทธิ์)
python3 tests/run_all.py attachments  # เฉพาะแนบหลักฐานใบเสร็จ/สลิป (ภาพสังเคราะห์ สิทธิ์ ล็อกปิดงวด)
python3 tests/run_all.py monthclose   # เฉพาะปิดงวดรายเดือน (ล็อกรายการ/โอน/ยอดยกมา เปิดงวดต้องมีเหตุผล)
python3 tests/run_all.py reportstatus # เฉพาะติดตามการส่งรายงานประจำเดือน
python3 tests/run_all.py approval     # เฉพาะรับรองรายงานเป็นลำดับชั้น (ตำบล→อำเภอ ส่งกลับ เปิดงวดอัตโนมัติ สิทธิ์ ก่อน/หลังรัน migration)
python3 tests/run_all.py recurring    # เฉพาะรายการประจำ (ถึงกำหนด ยืนยัน/แก้จำนวน/ข้าม ลบแล้วกลับมารอ ปิดงวด สิทธิ์ ก่อน/หลังรัน migration)
python3 tests/run_all.py reminders    # เฉพาะแจ้งเตือนอัตโนมัติทางอีเมล cron (ก่อน/เกินกำหนด ส่งกลับค้าง ปิดงวด สรุป staff ไม่ส่งซ้ำ เปิด/ปิด สิทธิ์ ก่อน/หลังรัน migration)
python3 tests/run_all.py search       # เฉพาะค้นหารายการขั้นสูง (กรองหลายเงื่อนไข ผลรวม แบ่งหน้า CSV สิทธิ์ ชุดกรองที่บันทึก ก่อน/หลังรัน migration)
python3 tests/run_all.py bangkok       # เฉพาะคำเรียก เขต/แขวง ของกรุงเทพมหานคร
python3 tests/run_all.py credits       # เฉพาะนโยบายเครดิต (ไม่ใช้ฐานข้อมูล): ผลงานของผู้อื่นที่ใช้ต้องมีเครดิตและสัญญาอนุญาต
python3 tests/run_all.py subdistrict  # เฉพาะเจ้าคณะตำบล + การสร้างผู้ใช้จังหวัด/อำเภอ/ตำบลอัตโนมัติ
```
รหัสออก: `0` ผ่านทั้งหมด · `1` มีข้อที่ไม่ผ่าน · `2` เชื่อมต่อฐานข้อมูลไม่ได้/ระบุชุดทดสอบผิด

## ความปลอดภัยของการทดสอบ
- รันบน **สำเนาโปรเจกต์ในโฟลเดอร์ชั่วคราว** (ไม่แตะ `config.local.php`, `storage/`, ไฟล์จริงของคุณ)
- ใช้ฐานข้อมูลชื่อสุ่ม `tfms_test_<สุ่ม>_*` และลบทิ้งทั้งหมดเมื่อจบ (แม้ทดสอบล้ม)
- เซิร์ฟเวอร์ SMTP ปลอมรับอีเมลในโปรเซส ไม่มีการส่งอีเมลออกภายนอก
- ตรวจ log ของ PHP ด้วย: มี Warning/Notice/Fatal/Deprecated ข้อใดข้อหนึ่ง = ไม่ผ่าน

## สิ่งที่ครอบคลุม
**features** (ติดตั้งด้วย `setup.php`): 1 วัด 1 บัญชี (unique), วัดที่ไม่มีอีเมลเข้าไม่ได้, แอดมินหลักลง/แก้/นำเข้าอีเมล, 2FA (รหัสผิด/ซ้ำ/หมดอายุ/ผิดครบ 5 ครั้ง/ขอใหม่เร็วเกินไป),
SMTP client (AUTH, UTF-8), ล็อกบัญชีเมื่อรหัสผ่านผิด 5 ครั้ง, เปลี่ยนรหัสผ่าน, ชื่อผู้ใช้/อีเมลแก้เองไม่ได้, สิทธิ์ (แอดมินวัดเข้า admin ไม่ได้),
วัดใหม่ได้บัญชีอัตโนมัติ, การตรวจพบ "ติดตั้งแล้ว" (มี/ไม่มีไฟล์ล็อก)

**install**: ตัวช่วยติดตั้งทุกขั้นและกรณีผิดพลาด (รวมการติดตั้งสำหรับจังหวัดอื่น: เลือกจังหวัด + อัปโหลด Excel / นำเข้าภายหลัง), (รหัสผ่านฐานข้อมูลผิด, ฐานข้อมูลที่มีข้อมูลอยู่แล้ว, รหัสแอดมินอ่อน, SMTP ผิด, CSRF), `TFMS_INSTALL_KEY`,
การล็อกหลังติดตั้ง (403), สิทธิ์ `config.local.php` 0640, CSV รหัสผ่านเริ่มต้นดาวน์โหลดได้ครั้งเดียว, และการบังคับเปลี่ยนรหัสผ่านครั้งแรกทุกกรณี

**people**: อัปโหลดโลโก้วัด/อำเภอ (ปฏิเสธไฟล์ไม่ใช่ภาพ/ใหญ่เกิน, แปลงใหม่ตัด payload), โควตาผู้ใช้ = อำเภอ+2 และ 1 คนต่ออำเภอ, สิทธิ์ดู/แก้/เปิดเลขบัตร (แอดมินอำเภอ/เจ้าคณะดูเลขเต็มไม่ได้), เลขบัตรเข้ารหัสในฐานข้อมูล+ตรวจหลักตรวจสอบ+ห้ามซ้ำ, เจ้าอาวาสได้คนเดียว, รูป/เอกสารเข้าถึงผ่าน media.php ตามสิทธิ์, หัวกระดาษรายงาน

**receipts**: QR code ตรวจสอบใบ (รหัสสุ่ม/หน้าสาธารณะปิดบังชื่อ/ไม่เปิดเผยข้อมูลเกินจำเป็น/ใบยกเลิก/รหัสผิด/ใบเก่าได้รหัส/app_url), แปลงจำนวนเงินเป็นตัวอักษร, ออกใบได้เฉพาะหมวดรับบริจาค, ตรวจข้อมูล/วันที่, เลขที่ต่อเนื่องและไม่ใช้ซ้ำหลังยกเลิก, ออกซ้ำรายการเดียวไม่ได้, รายการที่ออกใบแล้วแก้/ลบไม่ได้, สิทธิ์ข้ามวัด/อำเภอ, escape ข้อมูลผู้บริจาค, ตราระบบ

**auth** (เปิด `TFMS_STAFF_2FA=1`; ชุดอื่นปิดไว้เพื่อให้ล็อกอินแอดมินด้วยรหัสผ่านอย่างเดียว): ลงทะเบียน/เปลี่ยนอีเมลแอดมินหลัก, 2FA ของแอดมินหลัก/อำเภอ/เจ้าคณะจังหวัด, ผู้ใช้ไม่มีอีเมลเข้าไม่ได้, ลืมรหัสผ่าน (ตอบเหมือนกันทุกกรณี, รหัสใช้ครั้งเดียว/ผิด 5 ครั้งล็อก/ปลดล็อกบัญชี/รหัสผ่านอ่อนไม่ใช้รหัสทิ้ง/ผู้ใช้ปิดใช้งาน/ไม่มีอีเมล), audit ไม่มีรหัสหรืออีเมล

**ui**: แถวฟอร์มสูงเท่ากันชิดขอบล่างเดียวกัน (ตรวจ 10 หน้าในเบราว์เซอร์จริงถ้ามี Playwright) · ลูกศร dropdown และเดือนย่อในช่องวันที่ · ตัวควบคุมฟอร์มสูง/ขอบมนเท่ากัน (ตรวจ CSS + ไม่กำหนดเองในโค้ด + วัดจริงด้วย Playwright ถ้ามี) · การ์ดกลาง (.card/.card-table/.card-bar/.callout ถูกคอมไพล์ ไม่มีกล่องที่ประกอบสไตล์เอง ไม่มี padding ซ้ำบนการ์ด) · เมนูแบบกลุ่ม dropdown ของแอดมินหลัก (4 กลุ่ม ไม่มีลิงก์ซ้ำ เมนูมือถือตรงกัน) ไอคอน Feather ทุกชื่อที่เรียกใช้มีอยู่จริงใน sprite พร้อมไฟล์สัญญาอนุญาตและเครดิต กล่องแจ้งเตือนมีไอคอน และเลขเวอร์ชัน/บิวล์ในหน้าต่างเกี่ยวกับ · วันที่ทุกจุดเป็น พ.ศ. (ช่องกรอก/แสดงผล/CSV/ประวัติการใช้งาน, ปฏิเสธวันที่ไม่มีจริงและปี ค.ศ. ที่ใส่ผิดช่อง), HTML ที่ส่งออกใช้ `data-swal`/`data-confirm` ของ SweetAlert2 ไม่เหลือ `confirm()`/`alert()` ดิบ, ไฟล์ไลบรารีโหลดจากเซิร์ฟเวอร์เองและเปิดได้, flash แสดงครั้งเดียว, หน้าต่างเกี่ยวกับมีข้อมูลครบและลิงก์ภายนอกปลอดภัย (พฤติกรรมในเบราว์เซอร์ตรวจด้วยตา)

**import**: นำเข้า Excel ทะเบียนวัด — ไฟล์จริงของแพร่ 381 วัด (`tests/fixtures/Report_Temple_phrae.xlsx`) ให้ผลตรงกับ CSV เดิมทุกช่อง, หน้าตรวจก่อนนำเข้า, ไฟล์ผิดรูปแบบ/XXE/โทเคนปลอม, ไฟล์สังเคราะห์จังหวัดน่าน (สร้างอำเภอ ตั้งชื่อจังหวัด ลบอำเภอแพร่ที่ว่าง โควตา=อำเภอ+2 รายงานใช้ชื่อจังหวัดใหม่ อีเมลเฉพาะที่ว่าง), CSV ผ่านขั้นตอนเดียวกัน

**statements**: รายละเอียดบัญชีในหน้าข้อมูลวัด (เพิ่มบัญชีธนาคาร/ตั้งยอดยกมา/แบนเนอร์เตือน/สิทธิ์), โจทย์ตัวอย่างวัดสยามเทวา ม.ค.-ก.พ. 2568 จากโฟลเดอร์ ตัวอย่างเอกสาร — ยอดรวมรับ/จ่าย/ยอดยกไปของแบบที่ 1, แบบที่ 2 (กสิกรไทย/กรุงไทย), แบบที่ 3 (รวม + ตัวอักษร) ตรงกับเฉลยทุกช่อง, ชื่อผู้ลงนาม, เดือนที่ไม่มีรายการ/ก่อนวันเริ่มบัญชี, รายการโอนไม่นับซ้ำในสถิติและลบแล้วยอดย้อนกลับ, ตรวจข้อมูล (บัญชีซ้ำ/ข้ามวัด/วันที่ไม่จริง), สิทธิ์ข้ามวัด

## ข้อจำกัด (ยังไม่ครอบคลุม)
- SMTP แบบเข้ารหัส (STARTTLS/SSL) — เซิร์ฟเวอร์ปลอมรองรับเฉพาะแบบไม่เข้ารหัส ต้องทดสอบกับ SMTP จริงด้วยปุ่ม "ส่งอีเมลทดสอบ" ในตัวช่วยติดตั้ง
- Migration กับฐานข้อมูลรุ่นเก่า (`sql/migrations/`) — ทดสอบด้วยมือ
- หน้าตา/เลย์เอาต์ (ตรวจด้วยตาในเบราว์เซอร์)
- **CI**: `.github/workflows/tests.yml` รันชุดทดสอบทั้งหมดบน MariaDB 10.11 และ MySQL 8.0 ทุก PR/ทุกครั้งที่ push เข้า main (บัญชีทดสอบใช้ `mysql_native_password` เพราะไคลเอนต์ `mysql` ของชุดทดสอบเชื่อมต่อด้วยปลั๊กอินนี้)
- ทดสอบกับ MySQL ในเครื่อง: ตั้ง `TFMS_TEST_DB_HOST/PORT/USER/PASS` ชี้ไปที่เซิร์ฟเวอร์ MySQL 8.0 ที่มีบัญชีสร้าง/ลบฐานข้อมูลได้แบบ `mysql_native_password`

**install** ยังครอบคลุมการติดตั้งจังหวัดอื่นจากฐานข้อมูลจังหวัด (น่าน: ไฟล์ Excel + ผู้ใช้ 1+15+99 บัญชี, ภูเก็ต: ไม่มีไฟล์ทะเบียนวัด สร้างอำเภอ/ผู้ใช้ครบ)

**subdistrict**: เจ้าคณะตำบล — สร้างบัญชี/ตรวจข้อมูล (ตำบลไม่มีจริง ไม่เลือกตำบล รหัสอ่อน ชื่อซ้ำ), ไม่นับโควตา, ขอบเขตข้อมูลเฉพาะตำบลที่ดูแล (แดชบอร์ด รายงาน CSV รายงานแบบ 1 บุคลากร), เขียนไม่ได้ (บัญชีรายรับ-รายจ่าย อนุโมทนาบัตร ข้อมูลวัด จัดการระบบ), แก้ตำบล/อีเมล/รหัสผ่าน/ปิด-เปิด/ลบโดยแอดมินหลัก

**bangkok**: ติดตั้งกรุงเทพมหานครแล้วตรวจว่าทุกหน้าสำคัญ (แดชบอร์ด รายงาน ข้อมูลวัด รายงานแบบ 1 หน้าจัดการระบบ) ใช้ เขต/แขวง ไม่มี อำเภอ/ตำบลปะปน หัวเอกสารและที่อยู่ถูกรูปแบบ ชื่อบัญชีอัตโนมัติถูกต้อง

**credits**: นโยบายเครดิต — ไฟล์ใน assets/vendor และ assets/fonts ทุกไฟล์ต้องมีรายการใน data/credits.json, ไฟล์สัญญาอนุญาตมีจริง, CREDITS.md/เว็บประชาสัมพันธ์/หน้าต่างเกี่ยวกับตรงกับต้นทาง

**reportstatus**: ติดตามการส่งรายงานประจำเดือน — ส่งรายงาน (ยอดรวม ไม่นับรายการลบ/โอน) ส่งใหม่ แก้ไขหลังส่ง เดือนที่ยังไม่ถึงส่งไม่ได้ ขอบเขตของแอดมินหลัก/อำเภอ/เจ้าคณะตำบล/เจ้าคณะจังหวัด สิทธิ์ส่งแทนวัด อีเมลเตือน (เดือนละครั้ง ไม่ส่งถึงวัดที่ส่งแล้ว) กำหนดส่ง CSV ตัวกรอง และฐานข้อมูลเก่าที่ยังไม่รัน migration

**quick**: บันทึกด่วน — ฟอร์ม/เมนู/CSS บันทึกรายรับ-รายจ่ายแล้วกลับ quick.php ข้อผิดพลาด (จำนวนเงิน หมวดผิดประเภท ปิดงวด วัดอื่น) บัญชีธนาคาร สิทธิ์แอดมินอำเภอ/เจ้าคณะจังหวัด และหน้าบัญชีปกติไม่เปลี่ยนพฤติกรรม

**backup**: สำรองและกู้คืน — ไฟล์ .sql.gz จาก CLI/เว็บ ข้อมูลยาก (อัญประกาศ ขึ้นบรรทัดใหม่ อีโมจิ BLOB NULL) กู้ลงฐานข้อมูลใหม่แล้ว CHECKSUM TABLE ตรงกันทุกตาราง (รวมเวลา TIMESTAMP ข้ามเขตเวลา) ปฏิเสธเมื่อไม่ใส่ --yes ไฟล์กุญแจเข้ารหัส (รหัสผิด/ไฟล์ถูกแก้/รหัสสั้น) กู้พร้อม --key บนเซิร์ฟเวอร์ใหม่ ดาวน์โหลดกัน path traversal สิทธิ์แอดมินหลักเท่านั้น สำรองอัตโนมัติและการลบไฟล์เก่า

**bankimport**: นำเข้าจากไฟล์ธนาคาร — แปลงวันที่ (พ.ศ./ค.ศ./Excel/เดือนไทย) และจำนวนเงิน เดาหัวตาราง CSV หลายรูปแบบ (UTF-8 BOM, Windows-874, แท็บ, ช่องเดียว/ฝาก-ถอนแยก) และ Excel ตัวอย่าง จัดหมวด จำหมวดเดิม ตัดรายการซ้ำ แถวผิดปกติ แมปคอลัมน์เอง ไฟล์ไม่รองรับ ปิดงวด สิทธิ์ และ audit

**donors**: ทะเบียนผู้บริจาค — ต้องยืนยันความยินยอมก่อนบันทึก ที่อยู่/เบอร์เข้ารหัสในฐานข้อมูล ค้นหา แก้ไข เชื่อมกับอนุโมทนาบัตร (เลือกจากทะเบียน/สร้างใหม่พร้อมยืนยัน/ปฏิเสธผู้บริจาควัดอื่น) ประวัติและยอดรวม ถอนความยินยอม (ลบข้อมูลส่วนบุคคลแต่ใบเดิมคงสำเนา) สิทธิ์ทุกบทบาท audit และฐานข้อมูลที่ยังไม่รัน migration

**bankbook**: เพิ่มบัญชีธนาคารหลายบัญชีไม่จำกัด เลือกธนาคารจากรายชื่อ/"อื่น ๆ" ปฏิเสธรหัสผิดและบัญชีซ้ำ โลโก้แสดงในหัวบัญชี แนบ/เปลี่ยน/ลบภาพหน้าบุ๊คแบงก์ สิทธิ์ดูภาพข้ามวัด audit และฐานข้อมูลที่ยังไม่รัน migration

**images**: จัดการขนาดรูป — โปรไฟล์โลโก้/รูปถ่าย/หลักฐาน เก็บเป็น WebP คงสัดส่วนไม่ขยายรูปเล็ก คงความโปร่งใสของโลโก้ รับ WebP เป็นอินพุต และเครื่องมือแปลงรูปเดิม (ทดลองรัน/--apply/รันซ้ำ)

**assets**: ทะเบียนทรัพย์สิน — เพิ่ม/แก้/ตรวจข้อมูล (ชื่อ ประเภท มูลค่า เลขทะเบียนซ้ำ) รูป (แปลงใหม่ ลบรูปเดิม ปฏิเสธไฟล์ปลอม สิทธิ์เปิดรูป) ผูกรายจ่ายซื้อ/ซ่อม (ปฏิเสธทรัพย์สินวัดอื่น/จำหน่ายแล้ว ไม่นับรายการที่ลบ) จำหน่าย/ยกเลิก ตัวกรองและการค้นหา CSV กัน formula injection สิทธิ์ทุกบทบาท และฐานข้อมูลที่ยังไม่รัน migration

**funds**: กองทุน/โครงการและงบประจำปี — สร้าง/ตรวจชื่อซ้ำ/เป้ายอดผิด ผูกรายการกับกองทุน (ปฏิเสธกองทุนของวัดอื่นและกองทุนที่ปิด แต่แก้รายการเดิมได้) ยอดรับ/ใช้/คงเหลือไม่นับรายการที่ลบ วัตถุประสงค์เริ่มต้นของอนุโมทนาบัตร สิทธิ์ทุกบทบาท งบประจำปีเทียบปีก่อน/ยอดยกมา-คงเหลือ/งบประมาณ/กองทุน และฐานข้อมูลที่ยังไม่รัน migration

**budget**: งบประมาณประจำปี — บันทึก/ลบงบรายหมวด ค่าที่ไม่ใช่ตัวเลขไม่ทับของเดิม เมินรหัสหมวดผิด ผลจริงไม่ปนวัดอื่น/ไม่นับรายการที่ลบ เตือนที่ 80% และเกินงบตอนบันทึกรายจ่าย คัดลอกจากปีก่อน สิทธิ์ทุกบทบาท และฐานข้อมูลที่ยังไม่รัน migration

**reconcile**: กระทบยอดบัญชีธนาคาร — ยอดสมุด/เงินฝากระหว่างทาง/เช็คค้าง/ส่วนต่าง บันทึกทับเดือนเดิม เมินรหัสรายการของวัดอื่น เดือนที่ยังไม่สิ้นสุด รายการค้างยกไปเดือนถัดไป เตือนเมื่อข้อมูลเปลี่ยนหลังบันทึก สิทธิ์ทุกบทบาท และฐานข้อมูลที่ยังไม่รัน migration

**attachments**: แนบหลักฐาน — ภาพสลิปแนวตั้งคงสัดส่วน/ย่อด้านยาว 2000 px, PDF, ปฏิเสธไฟล์ปลอม (PHP/SVG/ข้อความ/ไฟล์เสีย), จำกัด 5 ไฟล์และ 4 MB, สิทธิ์ดู/แนบ/ลบทุกบทบาท, ล็อกเมื่อปิดงวด, รายการที่ลบแล้ว และฐานข้อมูลที่ยังไม่รัน migration (ใช้ภาพสังเคราะห์เท่านั้น ห้ามใช้สลิปจริง)

**monthclose**: ปิดงวดรายเดือน — เงื่อนไขปิด (ต้องส่งรายงาน ยอดตรง สิ้นเดือนแล้ว) การล็อกเพิ่ม/แก้/ลบ/ย้ายรายการ โอน/ฝาก-ถอน ยอดยกมา เพิ่มบัญชี ทุกบทบาท การเปิดงวด (เหตุผล สิทธิ์ ประวัติ) แก้ไขหลังเปิดต้องส่งรายงานใหม่ และฐานข้อมูลที่ยังไม่รัน migration (ผ่านการทดสอบแบบ mutation: ปิดตัวล็อกแล้วชุดทดสอบล้ม 11 ข้อ)
